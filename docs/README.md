## 目的
- 択捉島の作業の目的は、**架空路線の線形を作るノウハウを一般化し、単純な作業に分けてプログラムにすること**。線を作ること自体は目的ではない（2026-11-06、ユーザーの指定）。
- 作った線は、駅レーダーサイトのテスト版の確認用ページ（`src/test/align.html`）で見る。

## 最終的な目標（2026-11-06、ユーザー）
次の 2 つができるプログラムを作る。いま Claude が担っている探索・計算をプログラムにすることが目的。
1. GeoJSON などの作図から路線にする（いまの作業：経路 → 線形 → 縦断 → 走行）。
2. 地図の画面で駅の位置や通過する位置を入力し、計算の条件を指定して、最適な経路を求める。

動かし方（2026-11-06、ユーザー：Python のサーバーを立てるのは手間が大きい）：当面、計算の本体は Claude がクラウドの環境で動かす。
入力は、ブラウザだけで動く静的なページで地図の上で入れて入力表（JSON）として書き出し、ユーザーが Claude に渡す。
Claude が `build.py` で計算し、結果は確認用ページで見る。手順と判断の規則をプログラムと入力表に固めるのは、
どのセッションの Claude が動かしても同じ結果になるようにするため。

## 手順の段の正式な名前（2026-11-08、ユーザーと決めた。文書・報告・記録はこの名前で。「当てはめ」「探索」などの言い換えは使わない）
| 段 | 名前 | プログラム | 内容 |
|---|---|---|---|
| 1 | 経路の決定 | `devline_hybrid.py`・`devline3.py` | 作図の折れ線、または地形の上の面的な探索（A*）で、駅をつなぐ経路（折れ線）を決める |
| 2 | 平面線形の決定 | `ipfit_branch.py`・`ipfit_all.py`・`ipfit_fast.py` | 交点法：折れ線から交点を作り、交点の位置と円曲線の半径を動かして、ずれと走行時間の費用を最小にする。支線の分岐器の位置の決定を含む |
| 3 | 地形の取得 | `fit2route.py`・`ground.py` | 線形の上の 20 m ごとの点に地理院の標高タイルの地盤の高さを付ける |
| 4 | 縦断線形の決定 | `design3.py`（`structdp.py`） | 構造物の種類（土工・トンネル・橋梁）と施工基面の高さを、費用の表と規則（勾配の上限・駅の高さ・構内）で決める |
| 5 | 走行曲線の計算 | `keito2.py` | 系統ごとに車両の性能から速度と走行時間を計算する |
| 6 | 書き出し | `export.py`・`page/scripts/` | 駅レーダーサイトへ渡すファイルと、確認用ページのデータ |

- 共通ライブラリは当面作らない。両方で使う関数（`metres`・`project` など）は写して持ち、写した元を注釈に書く。画面を駅レーダーに合わせるとき（新しいアプリの画面は今は仮）に、改めて判断する。2026-11-03 の決定②（共通ライブラリは環境に依存しない部品だけ）は、これで保留にする。
- 確認用ページ：新しいリポジトリを公開し、GitHub Pages で見る。暗号化はしない（使ってはいけないデータは入っていない）。
- 受け渡し：駅の位置と路線の形は、今の作図と同じ形の GeoJSON。区間をまとめた路線の名前、系統、車両の性能、出典などの補足は、別の JSON。形の決まりは新しいリポジトリの最初の作業で文書にする。
- 共通のデータ置き場：freetrain-saves（非公開）を、両方のプロジェクトと FreeTrain の共通の置き場にする（名前は変える予定、【未定】）。置き場は「正本」で、各プロジェクトは必要なものを取り込んだ「写し」を持ち、取り込んだ版（置き場のコミット）を記録する（ビルドのたびに置き場を直接読む作りにはしない：駅レーダーの Actions は自分のリポジトリだけでビルドし、オフラインで再現できる決まりがあり、公開のページは非公開の置き場を読めないため）。置くのは、受け取ったものと、加工したもののうち共通の資料として使えるもの（ユーザーの判断）。加工したものには、元・作り方・使う側を README に書く。フォルダはセーブ・各島の作図・新しいアプリの書き出し・出典などに分け、要るフォルダだけを取り込めるようにする（セーブが約 219 MB あるため）。
- 新しいリポジトリの名前：`railroad-designer`（2026-11-07、ユーザーの判断。2 語まで、designer の響きを残す）。検討（サブエージェント 3 人＋検索）：railway は第一に「鉄道という輸送の仕組み」で、構造物の線路だけなら track・railway track・permanent way（Wiktionary・ウィキペディア英語版）。`railway-designer` は OSRD（Open Source Railway Designer、鉄道の施設設計のオープンソースの Web アプリ）と一致するので避けた。`track-designer` は鉄道模型のレイアウトのソフト（Track Designer など）やレースのコースの設計と受け取られやすい。`railroad designer` は米国で線路を設計する技術者の職名として使われ、同名のソフトは見つからなかった（railroad は主に米国英語、OSRD とは 1 語違い）。`line-maker` は直線と誤読されるので不採用。日本語の名前は【未定】（候補：線路デザイナー、鉄道線形デザイナー）。資料と報告は作業用フォルダの naming_src（控えなし）。
