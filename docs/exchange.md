# 駅レーダーサイトとの受け渡しの形（書き出し）

2026-11-07、⑤プログラム化の段 4。決定（`README.md`「分け方の決定」）：駅の位置と路線の形は、今の作図と同じ形の GeoJSON で渡し、
駅レーダーサイト（`hinoharu/eki-radar-dev`）の `scripts/fiction.py` を変えずに読めるようにする。区間をまとめた路線の名前、系統、
車両の性能、出典などの補足は別の JSON。精度は約 10 m の折れ線でよい。常時の連携はせず、書き出したファイルをユーザーが Claude に
渡して駅レーダーサイトに取り込む。

書き出すのは `kp/export.py`（`build.py` の最後でも呼ぶ）。置き場所は `export/`（島ごとに 6 ファイル。いまは択捉島だけ）。
共通のデータ置き場（freetrain-saves）に写す予定（HANDOFF.md「次にすること」6）。

| ファイル | 内容 | 駅レーダーサイトでの置き場所 |
|---|---|---|
| `<島>_lines.geojson` | 区間ごとの平面線形を折れ線にしたもの | `data/fiction_src/<島>_lines.geojson`（作図の線と置き換える） |
| `<島>_stations.geojson` | 駅の位置 | `data/fiction_src/<島>_stations.geojson`（同上） |
| `<島>_network.json` | 補足（区間、路線、系統、車両の性能、出典） | 置かない（取り込む Claude が読む） |
| `<島>_line_names.tsv`・`<島>_line_splits.tsv`・`<島>_yomi.tsv` | `fiction.py` が読む表の、この島の行 | 各表の、この島の行と置き換える |

島の名前はファイル名では `etorofu`・`kunashiri`（`fiction.py` の `ISLANDS` と同じ）。

## 1. 線の GeoJSON（`<島>_lines.geojson`）
- `FeatureCollection`。`Feature` 1 つが入力表 `kp/tables/sections.json` の区間 1 つ（`geometry` は `LineString`）。作図の線と同じ形で、
  `fiction.py` は `geometry` だけを読む。`properties` の `section`（区間の id）と `name`（区間の名前）は、補足の JSON と結ぶための付け足し。
- 座標は `[経度, 緯度]`（WGS 84、小数 6 桁＝約 0.1 m。作図と同じ）。向きは区間の起点から終点（入力表の `route.stops` の順）。
- 折れ線の作り方：線形の点（約 10 m 間隔。`fit_<区間>.json` の `A`）を、どの点も折れ線から **10 m** 以内に残る最少の頂点に減らす
  （Douglas–Peucker 法。しきい値は `thresholds.md`）。**駅の位置と、支線の分岐器の位置（幹線の上）は必ず頂点に残す**。したがって、
  駅はその区間の折れ線の上にあり、支線の端（分岐器の位置そのもの）は幹線の折れ線の頂点の上にある（座標の丸めで 0.1 m 以内）。
- 支線の端は分岐器の位置（`build.py` の線形の当てはめ ipfit_branch の結果。幹線の線形の上の 1 点）で、そこから先の幹線の駅までは
  含めない（線は重ねて描かない。作図と同じ）。`fiction.py` が、支線の端を幹線の上に載せ、路線を幹線に沿って次の駅まで延ばす（`_extend`）。
- スイッチバック駅で分けた区間（単冠山麓線の単冠山口、阿登佐線の散布泊）は、駅で 2 本の線が端点どうしで接する。

## 2. 駅の GeoJSON（`<島>_stations.geojson`）
- `FeatureCollection`。`Feature` 1 つが駅 1 つ（`geometry` は `Point`）。同じ駅は 1 回だけ：位置は、その駅を含む区間のうち
  **線の順位（`rank`）が最も高い区間**の線形の上（支線の端にある幹線の駅は、幹線の上の位置）。
- `properties.name` は作図と同じ決まり：駅は「名前＋駅」（例「蘂取駅」）、信号場・仮乗降場はそのまま（例「裡縫山信号場」）。
  `fiction.py` の `kind_name` がこの接尾辞で種類を決める。`properties.kana`（読み）は付け足し。
- 駅の名前は `data/fiction.json`（作図の結果）の表示名（フリートレインの名に替えたもの。例：宇遠知）。

## 3. 補足の JSON（`<島>_network.json`）
| 項目 | 内容 |
|---|---|
| `island`・`files` | 島と、組になるファイルの名前 |
| `built_with` | 書き出したときのこのリポジトリの HEAD のコミット（入力表か結果に未コミットの変更があれば、その旨を添える。書き出した結果をコミットするとそのコミットは 1 つ先になる） |
| `source` | 出典：作図、標高（国土地理院 DEM10B）、計算の方法（`align.md`） |
| `precision` | 折れ線のずれの上限（m）と座標の小数の桁 |
| `profile_keys` | 縦断の 2 通りの鍵：`free`（駅の高さを指定しない）、`gs`（駅地平化） |
| `sections[]` | 区間：`id`・`name`・`feature`（線の GeoJSON の何番目か）・`rank`（線の順位）・`grade`（線路の等級）・`parents`（つながる上位の区間）・`method`（`branch`／`legacy`）・`stations`（駅と起点からの距離 m）・`length_m`・`lines`（この区間が属する路線と、その範囲の駅）・`run`（線形の前提：VMAX・TILT・TRAIN）・`profile_input`（勾配の上限 GCAP、費用の表、複線の範囲）・`min_radius_m`（最小曲線半径）・`profile`（`free`・`gs` ごとに最急勾配 ‰・トンネルと橋梁の延長 m・縦断のファイル）・`polyline`（頂点の数と線形からの最大のずれ） |
| `lines[]` | 区間をまとめた路線：`name`・`kana`・`pieces`（区間 id と、その路線に属する範囲の駅）・`stations_drawn`（作図の路線の駅の並び） |
| `systems[]` | 系統：`id`・`name`・`sections`・`stops`・`car`（車両の形式・両数・性能の直接指定・出典）・`VMAX`・`TILT`・`TRAIN`・`run_min`（走行時間 分。`free`・`gs`）・`note` |
| `vehicles` | 使っている車両の性能（`kp/vehicles.json` の該当分。出典と引用を含む） |

路線の名前は、作図の路線（`data/fiction.json` の `routes`）から機械的に決める：区間の隣り合う駅の組が、作図のどの路線で隣り合うかで、
区間を路線の範囲に分ける。1 つの区間が複数の路線にまたがるのは特急の経路（蘂取線・留別線・蘂取線・振別線・老門線）だけ。
路線の名前を作図と変えたいときは、入力表に路線の表を加える【未定】。

## 4. `fiction.py` の表の行（`<島>_line_names.tsv`・`<島>_line_splits.tsv`・`<島>_yomi.tsv`）
`fiction.py` は、線 1 本を仮の名前「路線に沿った最初の駅〜最後の駅」で呼び、`line_names.tsv` でその名前を線名に対応させ、
同じ線名の線を 1 つの路線にまとめる。1 本の線を駅で分けるのは `line_splits.tsv`。この決まりに合わせて、書き出しが次の行を作る。
- `line_names.tsv`：線（分けたあとの線）ごとに、仮の名前 → 線名・読み。
- `line_splits.tsv`：(a) 複数の路線にまたがる区間を、路線の境の駅で順に分ける（特急の経路を紗那・南留別・類平・老門で 4 回。
  2 回目からの仮の名前は、分けたあとの「境の駅〜最後の駅」）。(b) 分けたあとに、同じ仮の名前で違う線名になる線（例：紗那〜南留別が
  蘂取線の区間 shibr と留別線）は、区間の 2 番目の駅で分けて避ける（shibr を留紗那で分け、両方とも蘂取線）。**(b) の行を (a) より先に
  置く**（`fiction.py` は行の順に分け、仮の名前が同じ線が 2 本あると最初の線を分けてしまうため）。
- `yomi.tsv`：駅の読み。鍵は「信号場」「仮乗降場」を除いた名前（`fiction.py` の `kind_name` と同じ）。

## 5. 駅レーダーサイトでの取り込み方
1. `data/fiction_src/` の `<島>_lines.geojson`・`<島>_stations.geojson` を書き出したものと置き換える。
2. `line_names.tsv`・`line_splits.tsv`・`yomi.tsv` の、その島の行を書き出した行と置き換える（他の島の行は残す）。
3. `stations_add.tsv`（作図にない駅を足す）と `station_renames.tsv`（表示名の置き換え）の、その島の行は外す（書き出しには足した駅が
   含まれ、名前は表示名になっているため）。
4. `python3 scripts/fiction.py` を実行し、路線と駅の数、読みのない駅が 0 であることを確かめる。

## 7. 分かっている制約・未定

  （特急の経路の 2 か所、shibr、shibw）に分かれると、2 本目がつながらず切れ目（gap）になる（作図では 2 本だった）。地図の線と駅には影響
  せず、未取得駅管理画面の駅の並びだけが 3 つに分かれる。直すなら `fiction.py` の組み立て（端がつながる線を長さに関わらず先に足す）。
