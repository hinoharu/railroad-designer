# 入力表（人が決める値の正本）

2026-11-06、⑤プログラム化の段 1。`build.py` がこの表を読み、経路から系統の走行までを計算する（段 2）。
初版は `gen_once.py` が、それまでのファイルとつなぎのスクリプト（chain_*.sh・rerun_*.sh）から作った（一度だけ使う。以後はこの表を直す）。
`net.py` は表を読む共通の部品で、`build.py` と `keito2.py`（区間の縦断のファイル名 DESIGN と線の順位 RANK）が使う。

## sections.json（区間の表。1 区間 1 行）
| 項目 | 内容 |
|---|---|
| id・name・rank・grade・parents | network.json と同じ（線の順位、線路の等級、上位の線とつながる所の説明） |
| island | 経路を探す島（`path.route` に渡す） |
| method | `branch`：build.py が計算する。`legacy`：古い手順のまま（特急の経路 ipg、散布線 sanpu）。build.py は計算せず、縦断のファイルの中身だけを下位の区間の判定に使う |
| route.stops | 駅の並び（つながる区間の駅から先へ）。経路は作図の線をこの順に最短でつないで作る |
| route.file | 経路のファイル。あれば使い、`--remake-route` のときだけ作り直す |
| route.turnback | 始点の駅の先の折り返し（スイッチバック駅の行き止まり）を除くか |
| route.turnback_end | 終点の側で同じことをするか（2026-11-07、国後島の仁岸寄） |
| route.hybrid | 地形から探して経路を作り直す（devline_hybrid.py の GDEF：既定の勾配の上限、GMAP：駅間ごとの上限、PREFIX） |
| route.hybrid.auto | 自動の探索（2026-11-07、国後島）：勾配で届かない駅間に加え、縦断に問題（準地平の外の駅＝トンネル駅・高架駅、BRIDGE_H1 超の橋梁）の残る駅間を `hyb_<id>_segs.json` に書き、`STAGES`（帯 W と費用の比 R の段。既定 [[300,3],[300,2],[600,2],[1000,2],[1500,2],[2000,2]]）の順に探して C(W) ≤ C(0)÷R の最初の段を採る。GDEF は profile.GCAP、非電化（KYAKU25_ADD）の駅間の GMAP は 25‰ を自動で置く。探す駅間が増えたら探索からやり直す（最大 3 回）。探した駅間の駅が範囲外のままなら、その駅間の探す勾配を 1‰ 下げて（`hyb_<id>_gseg.json`。10‰ まで）探し直す（択捉島で手で行っていた規則を自動にした）。`LAMBDA` を与えると連続的な基準：候補（元の折れ線、帯ごとの線）の「建設費＋LAMBDA×（元の折れ線から 30 m を超えて離れた分の面積 m²）」が最小のものを採る（勾配で届かない駅間の帯の選び方も同じ式。2026-11-07） |
| fit.trunk | 線形の当てはめ（ipfit_branch.py）の既定の幹線 |
| fit.ends | 端ごとの接続：`""` は既定の幹線、区間 id はその区間につながる。書かない端は、どの線にもつながらない |
| fit.free | どの線にもつながらない区間（スイッチバック駅で分けた後ろの区間など） |
| fit.junction | 分岐器の候補の制限（2026-11-08、ユーザーの指摘）：`JMIN` 停車場中心から分岐器までの最小距離 m（`"auto"` なら (TRAIN ＋ 20) ÷ 2 ＋ 32 m を列車長から計算する。TRAIN は支線と端の幹線の大きい方。根拠は `docs/junction.md`。支線を通る列車の進む側に置く。候補がすべて近いときは `JEXT`（既定 300 m）先まで候補を延ばす。幹線が駅で終わる所は今までどおり）、`GJ` 分岐点の本線の勾配の上限 ‰（超える候補を除く。残らなければ除かない）、`match_grade`（既定 true：支線の端の勾配を幹線の分岐点の勾配に合わせる。高さの指定表の `start_g`・`end_g`） |
| fit.dir | 端ごとの分かれる向きの指定：**支線を分岐点に向かって走ってきた列車が、幹線をキロ程の増える向きに進むなら `forward`、減る向きなら `backward`**（start・end どちらの端も同じ定義。例：国後空港線は空港 → 狩士別 → 白糠泊側（減る向き）なので backward）。書かなければ作図の支線の向きから判定（幹線とほぼ直角だと不安定。2026-11-07、国後空港線） |
| run | 線形の前提の最高速度 VMAX（km/h）、振子 TILT（0・1）、列車の長さ TRAIN（m） |
| profile.GCAP | 勾配の上限（0.025＝25‰） |
| profile.KYAKU25_ADD | 上限を 25‰ にする駅間（例：空港の前後） |
| profile.double | 複線の区間（駅の組） |
| profile.stations | 駅の高さの規則に対する例外。`free`（高さ指定なし）・`gs`（駅地平化）ごとに、駅名 → `[下, 上]`（地盤からの m）・`地平`・`指定なし` |
| profile.start_z_from | 始点の施工基面を、この区間の終点に合わせる（スイッチバック駅で分けたとき） |
| profile.rules | 縦断の規則の値（design3.py に環境変数で渡す。2026-11-07、国後島）：`BRIDGE_H1`（橋梁の高さの境 m。超える分に大きな罰則。0 で切）、`BRIDGE_H2`（峡谷の境 m）、`BRIDGE_SPAN`（峡谷とみなす、境を超える部分の長さの上限 m）、`W_BH2`（境を超える高さ 1 m あたりの重み）、`DEPTH_MAX`（駅の深さの上限 m。0 で切）、`EXIT_R`（出口を探す水平距離 m） |
| profile.STN_HALF | 駅の構内の半分の長さ m（停車場中心の両側で縦断を水平にする範囲。design3.py に環境変数で渡す。2026-11-08、分岐器の規則 `docs/junction.md` 2.④）：`"auto"` なら TRAIN ÷ 2 ＋ 72 m（有効長の余裕 20 の半分 ＋ 接触限界標から分岐器の理論交点まで 32 ＋ 分岐器の後端まで 10 ＋ 最端の転轍器の外方 20）。数値ならその値。書かなければ 110 m（それまでの値「8 両 160 m ＋分岐器」） |
| （構内の勾配） | 停車場ごとの構内の勾配の上限は、区間の表ではなく `station_yard.json`（停車場の種類）と `build.py` の `YARD_G`（棒線 10‰・分岐器あり 5‰）で決まる。縦曲線の延長 `VC_R` も同じ（2026-11-08、`docs/vertical_curve.md` 4） |
| profile.only_gs | 高さ指定なしの縦断を作らず、駅地平化だけにする（2026-11-07、ユーザー：国後島）。縦断のファイルは両方の鍵とも design_f<id>.json |
| src | 値を読み取ったスクリプト |

駅の高さの規則（build.py の make_spec）：駅地平化の側は、経路の全駅を地平（−2〜+2 m）にする。ただし、上位の線につながる端の駅と、
`start_z_from` の始点の駅は除く。端の施工基面は、上位の線の縦断の、分岐器の位置の高さに合わせる。

## station_yard.json（停車場の種類の表。1 停車場 1 行。2026-11-08）
FreeTrain のセーブ（`hinoharu/freetrain-saves` の 択捉島90x21_004re3_20260929…・国後島003_540x1584_20261025…）の線路の配置から `station_yard.py` が作る
（線路のマスは `save_rails.py` で取り出して `tables/saves/rails_<島>.json` に置く。1 マス ≈ 110 m）。
| 項目 | 内容 |
|---|---|
| kind | `棒線`：ホームに面する線路が 1 本で、ホームから 6 マス以内に分岐器のマスがない。`分岐器あり`：それ以外と、名前が「信号場」で終わる停車場（行き違いのための施設。セーブに分岐器がなくても） |
| tracks・junctions・platform_cells | ホームに面する線路の本数、6 マス以内の分岐器のマスの数、ホームのマスの数（判定の根拠） |
| save_name | セーブでの名前（信号場の「(信)」など） |
使う側：`design3.py`（構内の勾配の上限。表にない停車場は「分岐器あり」）。結果：185 停車場のうち 棒線 64・分岐器あり 121。支線がつながる分岐駅 33 はすべて分岐器あり。

## systems.json（系統の表。1 系統 1 行）
| 項目 | 内容 |
|---|---|
| id・name・sections | network.json と同じ |
| car_type・cars | 車両の表 vehicles.json の名前と両数（veh_env.py で性能にする） |
